# Совместимость с parseRM.pl

Чем `parserm-rs` отличается от оригинала `parseRM.pl` v5.8.2. Как пользоваться: [README.md](README.md).

## Баги оригинала повторены намеренно

Совпадение с оригиналом важнее, поэтому известные баги Perl воспроизводятся по умолчанию:

- `-edit` падает, как только повтор доходит до поиска класса: `Can't use string ("1") as a HASH ref`.
- `-a <файл>` оставляет колонку возраста пустой, а строка `Rage` в ландшафте получает ключом адрес ссылки.
- Строка `Kimura` в `.align` не применяется, а `-kim` действует только на `.out`.
- Числовой `-glen` игнорируется.
- Если div равен числу 0 (после `-kim` или `-my`) или строке `"0"`, следующий повтор затирает эту позицию, и она не считается двойной.

Флаг `--fix-quirks` (по умолчанию выключен, в сверку не входит) чинит `-edit` и применяет строку Kimura в `.align`.

## Принятые отклонения

- **Регулярные выражения Perl.** `-what <тип>,<шаблон> -contain` использует синтаксис Rust `regex`. Perl принимает lookaround и обратные ссылки, Rust нет. Rust завершается с ошибкой разбора шаблона до обработки входа, например для `-what 'name,L1(?=PA)' -contain`. Используй шаблон, который поддерживает Rust `regex`. Так сделано, чтобы сохранить текущий движок и ограниченное по времени сопоставление.
- **Имена файлов не в UTF-8.** Аргументы командной строки читаются через `args_os()` и `to_string_lossy()`. Неверные байты UTF-8 превращаются в символ замены, поэтому Rust может не найти файл, который Perl откроет. То же касается файлов, найденных через `-dir`: вывод `ls` декодируется через `String::from_utf8_lossy()`, а запасной обход файловой системы использует `to_string_lossy()`. Имя не в UTF-8 внутри папки может исказиться, даже если путь к папке в UTF-8. Так принято, потому что весь код работы с путями использует строки UTF-8. Используй имена в UTF-8: исходные байты имени не сохраняются.

## Известные отклонения (вне тестового корпуса)

Это вырожденные входы или случаи, где нужны внешние программы. Они описаны здесь и не воспроизводятся:

- `-w <тип>,` с пустым именем и `-c`: Perl использует последнее удачное регулярное выражение, которое зависит от разбираемой строки. Rust берёт пустой шаблон, он подходит ко всему.
- `-fa`: `sed 's/n\|N//g'` в BSD sed на macOS ничего не удаляет. Rust убирает N и n, как задумано. `-fa` и `-nrem` в сверку не входят.
- Координаты вида `0147`, `10.5`, `1e3`: Perl берёт исходную строку как ключ первой позиции, Rust берёт число. Координаты больше 2^53 приводят к ошибке завершения.
- Пустые поля div, del, ins (обрезанные строки заголовка) и значения div, равные NaN.
- Неверный `-l` (bin ≤ 0 или не задан): Rust сразу завершается с ошибкой, Perl зависает или пропускает ландшафт.
- Код возврата после `die` всегда 255. Perl берёт `$!`, если он задан. Тексты справки, usage и `-v` отличаются.

## Как это работает

Perl обходит каждый нуклеотид каждого повтора и держит несколько хэшей на каждую позицию. Здесь этот цикл заменён одним проходом по границам повторов (sweep line) на каждую последовательность генома (хромосому или контиг). Границы делят последовательность на элементарные отрезки. Каждый отрезок получает победителя (наименьший div, при равенстве первый повтор в файле) и число перекрытий. Затем каждый счётчик растёт сразу на длину отрезка, а медианы и средние берутся из взвешенных гистограмм. Время работы O(H log H) по числу повторов H, а не по числу замаскированных нуклеотидов.

Часть поведения Perl зависит от порядка обхода позиций (`sort keys`, то есть строковый порядок). Например, от этого зависит, в какую возрастную категорию попадёт фрагмент, лежащий в нескольких категориях. Чтобы воспроизвести это точно, код вычисляет лексикографически наименьшую позицию каждого интервала (`src/lexmin.rs`).
